## 2. 비슷한 수준의 두 안 — B4와 B5

| | **B4 요점 카드 (추천·기본)** | **B5 스마트 브리핑** |
|---|---|---|
| 느낌 | 밝은 민트, 카드형. 현행 B3를 다듬은 모습 | 짙은 남색 머리띠, 뉴스레터 앱 같은 미니멀 |
| 핵심 기사 | 제목 → 한 줄 핵심(꼭지 색) → 요점 3줄(라벨 칸) → 수치 카드 → **자세히(본문)** → MTC가 볼 것 | 왼쪽 큰 숫자 열 + 오른쪽 한 줄 핵심 · 요점 · "그래서 MTC는". **본문 없음** |
| 견본 글자 수(화면 글자) | 약 3,100자 | 약 2,700자 |
| 장점 | 본문이 있어 배경·조건이 궁금한 사람도 메일 하나로 끝. 현행 독자에게 낯설지 않다 | 가장 짧고 훑기 쉽다. 숫자가 먼저 눈에 들어온다 |
| 단점 | 스크롤이 B5보다 길다 | 배경·방식을 알려면 원문을 찾아야 한다(사내에서는 링크가 없어 번거롭다). 요점이 비면 내용이 부족해진다 |
| 바꾸는 법 | `newsletter_theme: B4` | `newsletter_theme: B5` |

**추천은 B4**입니다. 링크를 넣을 수 없는 사내 메일이라 "더 알고 싶을 때 갈 곳"이 메일 안에 있어야 하고, 요약층 덕분에 본문을 안 읽는 독자도 B5와 같은 속도로 핵심을 얻습니다.
B5는 독자가 대부분 임원이고 회신·문의로 깊이를 보충하는 운영이라면 더 맞습니다.

## 3. 사내 운영 전에 확인할 것

- 사내 모델이 `deck`·`points`를 실제로 잘 쓰는지 첫 호에서 확인한다(검토 요청 ②의 [D] 아래 ▶·· 줄로 보인다). 요점 문장 수정은 지금은 [E] 수정안 또는 `review/{주차}-draft.yaml` 직접 수정으로 한다. 검토 요청 문법에 요점 수정 칸(예: `D 핵심1.얼마나="…"`)을 넣는 일은 다음 작업으로 남겼다.
- 사내 메일 프로그램(Outlook 등)에서 B4·B5의 둥근 모서리·띠 색이 어떻게 보이는지 한 번 열어 본다. 표 기반·인라인 스타일이라 깨지지는 않지만 모서리는 각지게 보일 수 있다.

## 4. 2026-11-27 피드백 반영

- **30초 브리핑은 B4 방식으로 확정.** 꼭지(칩메이커·장비사 등) 구분 표시 없이 번호와 한 줄만 싣는다.
- **브리핑 한 줄은 유추가 필요 없게.** 핵심 기사의 한 줄 핵심(`deck`)은 주체 · 사건 · 결과를 모두 밝힌 완결 문장으로 쓰고, 한도를 40자에서 60자로 늘렸다.
  예: `삼성전자, 웨이퍼 결함 원인 분석에 AI 에이전트 적용…분석 시간 수 시간 → 수 분`.
- **점 막대(●●●○) 삭제.** 직관적이지 않아 뺐다. 성숙도·근거 유형은 카드 위에 글자 꼬리표(`현장 실증·적용 · 운영사 발표`)로 남긴다.
- **B 계열에서 벗어난 시안 2개 추가** (구조는 B4와 같은 세 층):

| | **E 에디토리얼(신문형)** | **S 스위스 볼드** |
|---|---|---|
| 느낌 | 미색 종이, 가운데 큰 명조 제호, 이중 괘선, 붉은 강조 하나. 신문 1면처럼 차분하고 무게감 있음 | 검정 머리띠와 노랑 띠, 아주 굵은 글씨, 기사마다 큰 번호, 두꺼운 괘선. 강하고 현대적 |
| 30초 브리핑 | 붉은 번호 + 가는 괘선 목록 | 검정 판 위 노랑 큰 번호 |
| 핵심 기사 | 붉은 작은 머리말(번호·꼭지) → 명조 제목 → 한 줄 핵심 → 괘선 요점표 → 큰 명조 숫자 → 명조 본문 → 붉은 줄 'MTC가 볼 것' | 큰 번호 + 제목 → 노랑 형광펜 한 줄 핵심 → 검정 라벨 요점 → 굵은 숫자 → 본문 → 노랑 띠 'MTC가 볼 것' |
| 어울리는 경우 | 임원 보고용, 신뢰감·격식이 중요할 때 | 사내 메일함에서 눈에 띄어야 할 때, 젊은 인상 |
| 주의 | 사내 PC에 명조 글꼴이 없으면 바탕체로 보인다 | 노랑·검정 대비가 강해 오래 읽으면 피로할 수 있다 |

## 5. 2026-11-27 두 번째 피드백 반영

- **디자인 후보: B4와 S.** E는 제외. S는 같은 구조에 색만 다른 S2(네이비·코랄)·S3(딥그린·라임)를 추가했다.
- **소식지 작성 수준 상향(설계서 9.6 작성 기준 8·9번 추가).**
  - 핵심 기사의 요점은 명사형 조각이 아니라 **완결된 3문장**(무슨 일 · 얼마나 · 어디까지, 각 90자 이내)으로 쓴다. 원문을 보지 않아도 대략적인 내용을 알 수 있어야 한다.
  - '자세히'는 요점을 되풀이하지 않고 배경·방식·조건을 2~3문장(200~320자)으로 보탠다.
  - **숫자는 의미와 함께**: 수치 카드에 '왜 중요'를 붙이고, 이번 주 한 방은 "누가 무엇을 잰 숫자인지 + 무엇과 비교해 왜 중요한지"를 쓴다(한도 120 → 160자).
  - 짧게 쓰는 곳은 30초 브리핑·단신·더 볼 거리뿐이다. 합계 한도 1,600 → 2,800자.

## 6. 2026-11-27 세 번째 피드백 반영 — 후보 B6 · S4

- **분량 2배**(사내 PC 메일 기준): 총론 140~240, 브리핑 한 줄 120, 요점 각 180, 자세히 400~640, 단신 90~150(2문장), 더 볼 거리 120, 한 방 320, 숫자 의미 80, MTC가 볼 것 160, 합계 5,600자. 견본 기준 본문 양이 약 1,400자 → 2,800자.
- **'왜 중요'를 따로**: 요점이 무슨 일 · 얼마나 · **왜 중요** · 어디까지 4개가 됐다. 브리핑 한 줄도 "무슨 일 + 왜 중요"를 함께 쓴다. 단신은 "무슨 일 + 왜 볼 만한지" 2문장.
- **숫자로 보는 이번 주**: 흩어져 있던 숫자를 한곳에 모아 숫자 · 무엇의 수치 · 왜 중요 · 기사 번호로 보인다.
- **쉬운 말**: 제목의 현장 용어에 수식어(`클린룸 아래 설비층 ‘서브팹’`), 괄호 풀이는 맨 위 한 줄 요약에서 처음 만날 때부터.
- **신뢰·가독성**: 보내는 곳 줄, 받은편지함 미리 보기 글, 이번 호 구성(구역별 건수), 이 메일을 받는 이유(받는 이유·만드는 방식·링크가 없는 이유·의견) 꼬리말.

| | **B6 브리핑 리포트** (B4 발전형) | **S4 매거진** (S 발전형) |
|---|---|---|
| 느낌 | 밝은 민트, 둥근 카드. 정돈된 업무 보고서 | 검정·노랑, 큰 번호와 굵은 괘선. 잡지 같은 강한 인상 |
| 숫자로 보는 이번 주 | 표(숫자 · 설명 · 기사 번호), 기사 카드에도 수치 칸 유지 | 2열 타일, 기사 카드에서는 수치 칸을 빼고 이 구역으로 모음(중복 없음) |
| 단신 | 2열 카드 격자: PC에서 한눈에 | 큰 번호 목록: 위에서 아래로 읽기 |
| 휴대폰 | 단신 2열이 좁아진다 | 한 열이라 휴대폰에서도 그대로 |
| 추천 | 사내 PC 메일이 주 경로면 B6 | 눈에 띄는 것이 중요하거나 휴대폰으로도 많이 보면 S4 |

## 7. 2026-11-27 경쟁 칩메이커 센싱·기술 이름·검색어 반영

- **주 목적**: 경쟁 칩메이커(SK hynix, Micron, TSMC, Intel Foundry, GlobalFoundries, UMC, SMIC, Kioxia, SanDisk, CXMT, YMTC, Nanya, Winbond, PSMC, Rapidus)의 **제조 AX·AI 동향**. 설계·개발·제품 출시·AI 칩 판매·실적 소식은 경쟁사 것이라도 찾지 않는다.
- **사외 탐색**: `queries.yaml`에 `competitors`(회사별 별칭·공식 채널·제조 용어 검색어 3~5개, 현지어 포함)를 두고, 모든 프롬프트 맨 앞에 `[최우선 목표]`, T1에는 `[경쟁사별 확인 목록]`(①~⑤ 확인 순서)과 출력 `coverage`를 넣었다. 리포트에 '경쟁사 탐색 범위' 표(회사 × 모델, complete 수)가 생기고, complete 0인 회사는 재조사 대상이 되어 재조사 T1 프롬프트 맨 앞에 나온다.
- **편성**: 핵심 최대 4(경쟁사 사건 최소 2건 먼저), 단신 최대 4, `core3_min_score` 삭제. 동점은 경쟁사 먼저. `selection.csv`에 `competitor` 열, 검토 요청 ① 표에 `[경쟁사]`. `config_version` 8, `issue_body_max` 9,000.
- **기술 이름·적용 범위·검색어**: 기사에 원문 이름 괄호(`결함 원인 분석 AI 에이전트(Defect Agent)`)와 "어디부터 어디까지" 범위를 쓰게 하고, `search_terms`(최대 3)는 인용 근거에 없으면 코드가 지운다. 발송본에 `🔎 검색어 · …`.
- **견본**: 핵심 4(앞 2건 + 가상 경쟁사 K·T) + 단신 4로 늘렸다. `python tools/render_sample.py --themes B6 S4`.
